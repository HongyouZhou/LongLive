# 08 — Reward-Weighted Velocity Matching Direction

**Date**: 2026-05-30

**Status**: design note for the next method direction.  This note records the
discussion after the per-reference protocol cleanup and the MP-EM-RAM
efficiency experiments in `docs/06.md` and `docs/07_per_reference_adaptation_protocol.md`.

---

## 1. Current Bottleneck

The active method is `longlive/methods/motion_projected_em_ram/`.

The current MP-EM-RAM loop is:

```text
E-step:
  sample K on-policy 4-step rollouts
  score each rollout with CoTracker direction + speed-ratio reward
  build an empirical reward-tilted distribution under a KL budget
  map importance weights to alpha_i = (w_i - 1)+

M-step:
  raw_shift    = (eps - x0) - v_default
  motion_shift = P_motion(raw_shift)
  target       = v_anchor + reward_coef * alpha_i * motion_shift
  loss         = ||v_default - sg(target)||^2 + beta_kl ||v_default - sg(v_anchor)||^2
```

The concrete code path is:

```python
target = v_anchor_d + alpha_eff * motion_shift
```

inside `motion_projected_em_ram_loss()`.

The core failure mode is that `alpha_i` mixes two different decisions:

1. **Rollout confidence**: should this sampled rollout influence the update?
2. **Velocity-shift magnitude**: how far should the target move away from the
   frozen LongLive anchor?

This is a structural coupling.  A noisy scalar reward can directly become a
large or small motion-amplitude target.  The reward ranks rollouts, but it does
not specify that the projected velocity shift direction is correct.

This diagnosis is consistent with the recent ablations in `docs/06.md`:

- hard reference-motion projection was too restrictive;
- feature-weight with mean normalization preserved full update mass for bad
  rollout groups and created motion artifacts;
- score-weighting fixed the full-mass artifact but over-rejected motion;
- component-feasibility was the best efficiency baseline, but still did not
  beat BASE motion fidelity.

The next objective should therefore stop using reward as a direct multiplier on
the velocity-shift magnitude.

## 2. Literature Signals

These references are design signals, not direct recipes.  The implementation
must still respect the LongLive setting:

```text
teacher   = fixed few-step LongLive product
reference = one video-level motion signal
student   = per-reference LoRA adapted on current on-policy rollouts
```

### 2.1 RTDMD

Reference:
`Reinforcing Few-step Generators via Reward-Tilted Distribution Matching`,
arXiv:2605.26108, 2026.

ArXiv abstract reports a reward-tilted teacher distribution view: minimizing
KL to a reward-tilted teacher decomposes into distribution matching and reward
maximization.  It targets few-step flow generators and combines distribution
matching distillation with reward-guided RL.

Useful signal for LongLive:

```text
reward should tilt which samples/gradients are emphasized,
while distribution matching keeps the generator near a valid teacher manifold.
```

Do not directly copy RTDMD.  It uses a broader image-generation RL/DMD setup,
including fake-score machinery and policy-gradient components that are heavier
than the current per-reference LoRA adaptation budget.

### 2.2 DMDR

Reference:
`Distribution Matching Distillation Meets Reinforcement Learning`,
arXiv:2511.13649, 2025.

ArXiv abstract frames DMD and RL as mutually useful: RL makes distillation more
preference-aware, while DMD regularizes RL and mitigates reward hacking.

Useful signal for LongLive:

```text
the LongLive anchor / DMD-style velocity preservation should be treated as a
reward-hacking defense, not as a separate afterthought.
```

For this project, that means the anchor loss should remain explicit when reward
weights are small.  A low-reward rollout should not become unconstrained; it
should be pulled back toward LongLive.

### 2.3 rCM

Reference:
`Large Scale Diffusion Distillation via Score-Regularized Continuous-Time
Consistency`, arXiv:2510.08431, ICLR 2026.

The arXiv abstract and NVlabs repository describe a forward-reverse divergence
joint distillation framework: sCM contributes a forward-divergence,
mode-covering consistency objective, and score distillation contributes a
reverse-divergence, mode-seeking regularizer.  The paper reports validation on
large image/video models including Wan2.1.

Useful signal for LongLive:

```text
pure reverse-style objectives are likely to be brittle for diversity and mode
coverage; a forward-KL / consistency interpretation is a better theoretical
anchor for per-reference adaptation.
```

However, an rCM-style consistency regularizer is not the immediate next
implementation.  It would add extra forwards and directly conflicts with the
current efficient-distillation goal.

## 3. Proposed Objective

The next method should be a **reward-weighted velocity loss**:

```text
target = v_anchor + shift_coef * P_motion(raw_shift)
loss   = anchor_beta * ||v_default - sg(v_anchor)||^2
       + w_i * ||v_default - sg(target)||^2
```

Key change:

```text
reward controls "how much to learn from this rollout",
not "how large the target shift is".
```

The shift magnitude is controlled by a fixed trust coefficient:

```yaml
shift_coef: 0.25  # or 0.5 after a small ablation
```

The sample weight `w_i` can reuse the existing EM machinery:

```text
q_i proportional to exp(A_i / eta)
w_i = N * q_i
```

with the current KL-budget bisection solving the temperature.  This avoids
introducing a new fragile `exp(reward / T)` temperature sweep as the first
variant.

Important implementation detail:

```text
anchor_beta must stay active even when w_i is small.
```

Otherwise low-reward samples would contribute almost no gradient and would no
longer preserve the LongLive distribution.

---

## 4. Relationship To EM-RAM

This is not a rejection of EM.  It changes where the EM information enters.

Current MP-EM-RAM:

```text
EM tilt -> alpha_i -> target amplitude
```

Proposed reward-weighted variant:

```text
EM tilt -> loss weight w_i
fixed trust coefficient -> target amplitude
```

The E-step still selects a local reward-tilted empirical distribution.  The
M-step no longer lets the scalar reward directly rescale the velocity residual.

This also clarifies the role of component-feasibility:

```text
component weights should modulate w_i / feasibility,
not preserve update mass by changing alpha while target amplitude remains
reward-dependent.
```

---

## 5. Forward-KL Framing

The proposed loss can be interpreted as a local approximation to an
on-policy, reward-tilted forward-KL update.

Ideal target distribution:

```text
q_ref(x) proportional to p_teacher(x) * exp(r_ref(x) / eta)
```

Direct sampling from `q_ref` is unavailable.  Near initialization, the student
LoRA is close to the LongLive teacher, so:

```text
p_student(x) approximately p_teacher(x)
```

and the forward-KL gradient can be approximated with importance weights on
student on-policy samples:

```text
loss = sum_i w_i * ||v_student(x_i, t) - target_teacher_tilted(x_i, t)||^2
```

In the first executable variant, `target_teacher_tilted` is approximated by the
LongLive anchor plus a fixed-size projected RAM residual:

```text
target_teacher_tilted = v_anchor + shift_coef * P_motion(raw_shift)
```

This gives a cleaner theoretical story than the current `alpha_i * shift`:

```text
reward tilts sample importance;
LongLive anchor preserves the teacher manifold;
motion projection defines the allowed adaptation subspace.
```

## 6. Implementation Plan

Keep the implementation inside `longlive/methods/motion_projected_em_ram/`.
Do not create a new method directory yet.

Add a config switch:

```yaml
mstep_objective: reward_weighted_velocity  # default remains current behavior
shift_coef: 0.25
loss_weight_mode: em_weight
loss_weight_clip_min: 0.0
loss_weight_clip_max: 2.0
anchor_beta: 0.1
```

Implementation shape:

1. Extend `em_tilt_weights()` or add a sibling helper to return both:
   - `alpha = (w - 1)+` for existing MP-EM-RAM;
   - `w = N * q` for reward-weighted velocity loss.
2. Add a loss function variant:

```python
target = v_anchor + shift_coef * motion_shift
motion_loss = per_sample_mse(v_default, target.detach())
anchor_loss = per_sample_mse(v_default, v_anchor.detach())
loss = (w * motion_loss + anchor_beta * anchor_loss).mean()
```

3. Preserve the existing `coarse_motion` projection as the first variant.
4. Keep per-reference protocol unchanged.
5. Run the same two sentinel units first:
   - `ucf_Golf-Swing_r00`
   - `loveu_miami-surf`

The first experiment should answer only one question:

```text
does decoupling reward confidence from shift magnitude fix the UCF failure
without destroying the LOVEU positive case?
```

## 7. Deferred Directions

### 7.1 Per-Frame Reward Decomposition

CoTracker already has per-frame tracklet information, but the current reward
API returns only one rollout scalar and a few aggregate components.

The full per-frame variant is promising:

```text
frame_reward[t] -> frame_weight[t] -> time-local velocity update
```

but it should not be the immediate next implementation.  Mapping CoTracker
frames to latent frames / anchor timesteps can introduce a new confound.

Safer first version:

```text
2 or 3 temporal buckets: early / middle / late
```

Only attempt this after reward-weighted velocity loss has a clean 2-video
sentinel result.

### 7.2 Consistency Regularizer

An rCM-inspired consistency term is theoretically attractive for mode coverage,
but it adds extra forwards.  Since the current project target is efficient
per-reference adaptation, this is lower priority.

Use it only if reward-weighted velocity loss improves motion but begins to
collapse prompt diversity or subject-swap behavior.

Immediate next experiment after the running baseline-relative job:

```text

```

Suggested starting hyperparameters:

```yaml
outer_epochs: 4
inner_steps: 8
k_rollouts: 4
g_endpoints_per_outer: 4

mstep_objective: reward_weighted_velocity

loss_weight_clip_min: 0.0
loss_weight_clip_max: 2.0
anchor_beta: 0.1

em_target_kl: 0.02

```

Compare against the same sentinel anchors:

- BASE per-unit scores from `per_reference_em_ram_subset`;
- raw EM-RAM final and `lora_5`;
- absolute MP-EM-RAM 4x8;
- baseline-relative MP-EM-RAM 4x8.

Success condition:

```text
UCF Golf-Swing must not collapse below raw EM-RAM / absolute MP-EM-RAM, and
LOVEU miami-surf should keep the motion_fidelity gain seen in the positive
absolute MP-EM-RAM run.
```

If this fails, the next diagnosis should inspect whether the motion projection
itself is wrong for UCF, rather than adding another scalar reward gate.
