## 3. amplitude collapse(协议外的代价)

### 3.1 为什么去看

用户视觉 review 8 对 paired videos(`d7e4bf6f` bear-skate / `c61ccfd8` lion-skate 等)后反馈:**"baseline 动态更明显,但错误更多"**。metric 报 Phase 3 全面胜利,直觉报 Phase 3 motion 不如 baseline 大。两者矛盾必有 metric 盲点。

`scripts/motion_eval/metrics/motion_fidelity.py` 实现是 Yatim et al. 的 **CoTracker3 tracklet velocity cosine similarity** — cosine 只看方向,**完全不惩罚幅度衰减**。一个"运动更少、方向更准"的视频可以拿更高 motion_fid。

### 3.2 测什么

`scripts/local/amplitude_analysis.py`(post-hoc,纯 numpy,读已有 CoTracker cache):

- **mean_velocity_px** = 每对相邻帧可见 tracklet 的 ‖v‖ 均值(pixel/frame)
- **total_path_px** = 单 tracklet ∑‖v‖ 然后平均
- **max_displ_px** = 单 tracklet 相对 t=0 最大位移然后平均

不需要 reference,纯描述生成视频自身有多"动"。

### 3.3 结果

| Metric | baseline | Phase 3 | Δ |
|---|---:|---:|---:|
| mean_velocity_px | 4.84 | **1.59** | **−67%** |
| total_path_px | 58.5 | 22.1 | −62% |
| max_displ_px | 41.9 | 16.6 | −60% |
| motion_fid (cosine) | 0.390 | 0.430 | +10.3% |

**Phase 3 视频的 motion 量是 baseline 的 1/3。** 这不是"略弱",是塌陷。

UCF 按类别:**amplitude 塌的幅度与 motion_fid 提升幅度强负相关**:

| Category | Δ amplitude | Δ motion_fid |
|---|---:|---:|
| ★ Skateboarding | **−81.4%** | **−2.5%** |
| Run-Side | −73.2% | +10.7% |
| Riding-Horse | −66.9% | +27.3% |
| Walk-Front | −65.4% | +49.3% |
| Diving | −63.2% | +38.2% |
| Lifting | −61.4% | +12.2% |
| Swing-Bench | −18.7% | −4.9% |

Skateboarding 是训练域,amplitude 塌得最狠(−81%),所以即使 cosine 方向更准,绝对值也吃不下"幅度从 13.5 → 2.5"的损失,total motion_fid 还是 −2.5%。其他类别 amplitude 塌少一点(50-65%),cosine 提升占主导。

**Reframed headline**:"Phase 3 在 MotionDirector eval 协议上,以 2/3 motion amplitude 为代价换取了 +10% motion 方向准确度。协议本身不报 amplitude,所以这个 trade-off 在 paper 表格上隐形。"

## 4. alpha sweep — 定位 root cause

### 4.1 假设

Phase 2 用 MotionDirector loss(`L_temporal_MSE + L_AD` with β=1),L_AD 显式惩罚帧间外观变化,推测它**隐式压 amplitude**。LoRA inference-time `lora_alpha` 决定 LoRA 注入强度(`scaling = alpha/rank`),如果 alpha 是有效旋钮 → "Phase 2 LoRA 把 amplitude bias 注入 teacher" 假设成立 → Phase 3 用更小 alpha 重训可恢复 amplitude(无需重训 Phase 2)。

### 4.2 实验

`scripts/hpc/sbatch_motiondirector_alpha_sweep.sh`(SLURM job `8913522` + retry `8913905`):
- 同一 `teacher_lora_final.pt`,inference 时 reattach 不同 `lora_alpha`
- α ∈ {64, 32, 16, 8} × 6 paper Skateboarding prompts = 24 videos
- full-step Wan-14B(50 UniPC),不动 Phase 3
- CoTracker3 算 amplitude(`scripts/local/amplitude_sweep_analysis.py`)

输出 `$LL_DATA/motiondirector_runs/skateboarding_v1/alpha_sweep/amplitude.csv`。

### 4.3 结果(null)

| alpha | n | mean_v_px | path_px | max_d_px |
|---|---:|---:|---:|---:|
| 64 | 6 | 10.05 | 69.27 | 56.25 |
| 32 | 6 | 11.27 | 75.65 | 62.36 |
| 16 | 6 | 10.68 | 68.05 | 56.08 |
| 8  | 6 | 10.15 | 63.86 | 48.20 |

**alpha 64 → 8(LoRA 强度降到 1/8),mean_v 几乎不动(10.05 → 10.15)。无单调趋势,所有点 ~10 px/frame**。

### 4.4 Reframe

把所有 amplitude 数字摆在一起:

| Setup | denoising steps | Phase 2 LoRA | Skateboarding amp |
|---|---:|:---:|---:|
| baseline(4-step student,no LoRA) | 4 | — | **13.52** |
| Phase 3 student | 4 | rank=64 α=64 | **2.51**(−81% vs baseline) |
| Sweep α=64 | 50 | rank=64 α=64 | **10.05** |
| Sweep α=8 | 50 | rank=64 α=8 | **10.15** |

**Phase 2 LoRA 本身不杀 amplitude**(full-step teacher 加 LoRA,10 px/frame,接近 baseline)。**塌发生在 DMD 蒸馏 4-step student 的过程里**(teacher 10 → student 2.5)。

§3.3 的解读("Phase 2 LoRA 是 generic motion prior")**部分错**:Phase 2 LoRA 没塌 teacher amplitude,§3.3 看到的 +20% UCF 提升大概率是 student 在 9 个非训练类别里"还能动一点"的 cosine 信号,而 Skateboarding 训练域被 amplitude 塌得最狠所以连 cosine 都救不回。

## 5. 当前知识边界

**已确认**:

- 两阶段架构(Phase 2 MLE teacher LoRA + Phase 3 DMD distill)端到端可行,无核心代码改动(L5 trainer 子类 + L1 lora_utils elif 注入位置)。
- 4-step student 在 MotionDirector eval 协议上 net positive(+10.3% motion_fid)。可作 paper 数字。
- Phase 3 amplitude vs baseline = **0.33×**,structural 不是 noise。
- Amplitude collapse **不是 Phase 2 LoRA 强度的问题**。inference-time alpha 不是有效旋钮。

**未确认 / 未测**:

- 没测 "no Phase 2 LoRA + full-step Wan-14B" amplitude(可推断 ≥10,因为去掉 LoRA 应该更松,但没数)。
- 没测 student LoRA(rank 256)inference-time alpha 扫,可能 student 自身 LoRA 强度才是真正的旋钮。
- 没测 DMD 4-step student 在 "no Phase 2 LoRA" 下的 amplitude(只有 baseline 13.52,baseline 是 student 训练的;不是同一 student 卸下 LoRA 跑 inference)。
- 没测 DMD 用别的 denoising_step_list(5/6/8 步)是否缓解 collapse。

**结构性 ceiling 假设**:DMD 的 reverse-KL 是 mode-seeking,4-step 表达力有限,student 倾向收敛到"低能量 / 小幅度"模式。Phase 2 LoRA 改变 teacher 分布但不改 mode-seeking 性质 → collapse 是 DMD-4-step 框架本身的属性。**这是 idea 层面的硬约束,不是参数能修的。**

## 6. 下一轮 idea 方向(docs/06 候选)

不在本文档拍板,只列。三条都需要先纸上想透再写代码:

1. **加 motion-aware 训练信号到 student**(不是 teacher)。在 DMD reverse-KL 之外加一个 amplitude / tracklet-aware 项。需要先想清楚 loss 形态,且要确认这不会跟 DMD 梯度对冲(参 docs/02 旧 motion-DMD 路线已被推翻的教训)。
2. **换 distillation 算法**。consistency / progressive distillation 的 mode-coverage 性质与 DMD 不同,可能不塌 amplitude。代价:换 framework。
3. **重新定义问题**。motion customization 也许根本不应该走 distillation。conditioning(motion token / control signal / motion-aware sampling)是另一类 prior 注入路径,不受 DMD-4-step ceiling 约束。

**不在候选**:
- 在 Phase 2 / Phase 3 调参修 amplitude — 已证 alpha 无效;改 β / steps / rank 是 §5 结构性 ceiling 之内的局部位移,不会越过 ceiling。
- Phase 3 离开 LongLive 上游默认 — 用户原则:**"调参应该是 idea 确定下来以后做的事情"**。

## 8. Retrospective

**做对了的**:

- 先 trust the metric(出 +10.3% 数字),后 verify with eyes(用户 review videos → 反直觉信号),再用 post-hoc analysis 算 amplitude — 序贯诊断,没有过早下结论。
- alpha sweep 在投入 Phase 2 重训之前先做 — 1.5h + 16min 而不是 1.5h + 29h,把 null result 揭出来。
- 没在 amplitude collapse 出来后立即跳到 "重训 Phase 2 改 β" — 用户原则 "idea 没定不调参",强制把 finding 落 docs 而不是再投 GPU。

**没做对 / 教训**:

- §3.3 "Phase 2 LoRA 是 generic motion prior" 的解读基于 UCF per-category 数字,**没考虑 amplitude collapse 已经 dominates**。如果先做了 amplitude 分析再读类别表,就会知道 +20% 不来自"Phase 2 学会了 motion",而来自"non-trained 类别 amplitude 塌少一点"。
- alpha sweep 用 4 个 alpha 但只看了 UCF Skateboarding 6 prompts。如果各 alpha 在 motion_fid 上的表现也跑一遍(需要 reference clips),会知道 LoRA 强度对 cosine 的影响,不止 amplitude。下次:**新 metric 出现时,把 paper 协议的 metric 一起跑,不要分两步**。
- `chnsu` 是 shell alias,`timeout chnsu ...` 不认 — `hpc-up` 初版在 sbatch 之外卡了一会儿才发现。教训:script 里走 binary path,不依赖 alias。
