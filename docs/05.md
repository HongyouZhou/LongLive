# 05 — Fast adaptation 路线总结: NFT × 4 failed, RAM-v1 works, DRaFT-K memory-wall

**Anchor**: [04.md](04.md) DiffusionNFT 设计 spec(实施后的结论汇总在这里),supersedes 03.md / 02.md / 01.md 的具体方法选择。

**Status**: 三条路实验完整跑完(2026-05-15 至 2026-05-22)。RAM-v1 是当前 working baseline,NFT 家族 + DRaFT-K 已不再深追。

**Update 2026-05-26**: `longlive/methods/diffusion_nft/` has been deleted as an
active method. New exploration should use
`longlive/methods/on_policy_context_distillation/`, focusing on current-student

**Target product 回顾**: runtime 给一个 reference motion clip → ≤ 30 分钟出一个 LoRA → 直接挂上 `longlive_base.pt` 用。**RAM-v1 满足这个目标**(20 outer × 16 inner ≈ 50 min on 8 H200,VBench Total 与 BASE 持平)。

## 1. 一句话

NFT 家族 4 次试验全失败(NFT / NFT-H1 / NFT-H3 / NFT-H3' — β-interp + EMA self-mirror 在 4-step DMD ceiling 下 r ≈ 0.5 退化 + caption collapse),独立派生的 RAM(arxiv:2605.10759 — frozen anchor + multiplicative target shift + single MSE)在第一次试验上 PASS 所有 acceptance criteria(VBench Total 83.07 ≈ BASE 83.09,Quality 84.86 > BASE 84.77),DRaFT-K(arxiv:2309.17400 reward-gradient backprop)在我们的 21-frame causal video DMD 上是架构性 memory-prohibitive(5 次 smoke 全 OOM / CheckpointError,~98 GiB snapshot 比 activation 还贵),已弃。

## 2. NFT family — 4 次都不上线

NFT 设计已在 [04.md](04.md) 锁定。实施时按"假设修复阶梯"逐步松绑约束,4 个 ckpt 全在 3-table 上不合格。

### 2.1 NFT(initial,JID 8969217/8969218)

按 04.md 配置直跑:LoRA rank 32 / α 64,K=4,β=1.0,β_KL=1e-4,EMA `decay = min(0.001·step, 0.5)`。

| | UCF mf | LOVEU mf | VBench Total | Semantic |
|---|---:|---:|---:|---:|
| BASE | 0.348 | 0.398 | 83.09 | 76.36 |
| NFT | 0.21 | 0.25 | 71.68 | 62.69 |

**诊断**: log 显示 K=4 rollouts 经常 `group_collapsed=5/20`(组内 std ≈ 0,reward 信号失效)。rank-local group_norm 噪;EMA decay=0 起步 → `v_old ≈ v_default` → β-interp 两支 degenerate(`v_θ^+ ≈ v_θ^- ≈ v_θ` 自相似)。reward 进 loss 是 `[r, 1-r]` mixture,r ≈ 0.5 时退化,LoRA 自我蒸馏方向 random,motion direction 反向。

### 2.2 NFT-H1(JID 8969840)

H1 = 两个 root-cause 同时修:
- Cross-rank `dist.all_gather` 让 group_norm 跨 ranks 算 std(group 从 K=4 扩到 K=32),解 group_collapsed
- EMA decay 起点 `ema_ramp_rate=0.05`(原默认是 0),让 `v_old` 一开始就跟 `v_θ` 有差距

| | UCF mf | LOVEU mf | VBench Total | Semantic |
|---|---:|---:|---:|---:|
| BASE | 0.348 | 0.398 | 83.09 | 76.36 |
| NFT | 0.21 | 0.25 | 71.68 | 62.69 |
| NFT-H1 | 0.12 | 0.19 | 81.76 | 75.06 |

**诊断**: VBench Semantic 拉回到 75.06(close to BASE 76.36),意味着 caption alignment 不破了 — group_norm 噪是真问题。但 motion fidelity **掉得更狠**(0.21 → 0.12);Dynamic Degree 飙到 95.83(BASE 50)说明 motion amplitude **overshoot** — 不是 motion 失败,是方向错。NFT-H1 解了 reward signal 传递问题,但 amplitude direction 自己飘了 → 这是 DMD 4-step 内禀 amplitude ceiling 撞墙(详见 [memory `dmd-4step-amplitude-ceiling`])。

### 2.3 NFT-H3(JID 8972526)

H3 = "扔掉负分支" — 04.md §8.1 列的极端 fallback。`positive_only RFT`:`loss = r · ‖v_θ − v‖²`,β-interp 不再用。同时把 rank 从 32 升 64,看看更大 capacity 能否吃住信号。

| | UCF mf | LOVEU mf | VBench Total | Semantic |
|---|---:|---:|---:|---:|
| BASE | 0.348 | 0.398 | 83.09 | 76.36 |
| NFT-H3 | -0.00 | 0.01 | 57.97 | **12.06** |

**严重 caption collapse**(Semantic 12.06 vs BASE 76.36)。motion_fidelity 直接归零。

**诊断**: positive-only RFT 没有 contrastive anchor,LoRA 漂到 random direction,跟 caption 完全脱钩。

### 2.4 NFT-H3'(JID 8973320)

H3' = 用 β_KL 拉住:`β_KL` 从 1e-4 拉到 1e-2(100×),rank 回 32(怀疑 rank 64 给了太多漂移空间)。

| | UCF mf | LOVEU mf | VBench Total | Semantic | DD |
|---|---:|---:|---:|---:|---:|
| BASE | 0.348 | 0.398 | 83.09 | 76.36 | 50.00 |
| NFT-H3' | 0.38 | 0.32 | 60.33 | **13.59** | **100.00** |

mf 看起来"恢复"了(0.38 > BASE 0.35),但:
- Semantic 13.59(还是 collapse)
- DD 100.00(motion amplitude 极端 overshoot,几乎是 BASE 的两倍)

**诊断**: motion_fidelity 高是 artifact —— amplitude overshoot 让 tracklet velocity 方向变化大,跟 ref 的 tracklet 巧合 cosine 高。视觉上不一致(Semantic 灾难性 collapse)。

### 2.5 NFT family 总诊断

阶梯走完,定论:

| 问题 | 实证 |
|---|---|
| β-interp `[r, 1-r]` mixture 在 r ≈ 0.5 退化 | NFT / NFT-H1 |
| EMA `v_old` 是 `v_θ` 的滞后镜像,不是 frozen anchor → self-drift | 整个家族 |
| K=4 group-norm 在 DMD 4-step ceiling 下 amplitude 不可控 | NFT-H1 DD 95.83, NFT-H3' DD 100 |
| 扔负分支或加重 KL 都救不了 caption alignment | NFT-H3 / H3' |

NFT GitHub Issue #46(velocity collapse on constrained network)在我们的 video few-step setting 上确认成立。**β-interp + EMA 的 NFT 形式不适合 few-step DMD video**。

## 3. RAM-v1 — 第一个不破 BASE 的方法

NFT 家族失败后,读 RAM paper(Bergmeister et al., arxiv:2605.10759, 2026-05),发现它是**独立派生**的 RL post-training 方法(不是 NFT 变体,虽然 Section 5 直接 cite 并对比 NFT)。三个关键差异恰好对应 NFT 的三个失败模式。

### 3.1 算法

RAM Eq. 17(v-space 形式):

```
target = v_ref + reward_coef · r · ((ε − x_0) − v_default)
loss   = MSE(v_default, target)
```

跟 NFT 对比:

| | NFT | RAM |
|---|---|---|
| Anchor | `v_old` = EMA of `v_θ`(self-mirror,drifting) | `v_ref` = frozen pretrained base(zero-init `anchor` PEFT adapter,不动) |
| Reward 入 loss | `[r, 1-r]` mixture coefficient | Multiplicative target shift coefficient |
| Loss 形 | `‖v_θ^+ − v‖² − ‖v_θ^- − v‖²`(±β contrastive) | 单 MSE,无 contrastive |
| Degenerate region | r ≈ 0.5 时两分支退化 | `r → 0` 时 target 退化到 `v_ref` → 强 anchor 到 base |

三个差异分别 fix 了 NFT 的三个失败模式:不会 self-drift,不会 r=0.5 degenerate,不触发 velocity collapse failure mode。RAM paper §5 / Table 2 直接 claim "RAM avoids the severe quality collapse of DiffusionNFT and AWM",我们用 NFT 失败实验确认了这个 claim。

### 3.2 Locked params(`longlive/methods/diffusion_ram/configs/skateboarding_ram.yaml`)

| 参数 | 值 |
|---|---|
| outer_epochs / inner_steps / k_rollouts | 20 / 16 / 4 |
| LoRA rank / α | 32 / 64(跟 NFT 同,可直接比) |
| reward_coef | 1.0(motion_fidelity continuous in [-1, 1],paper 在 binary partial-credit reward 上用 100/1000,我们 continuous 从 1.0 起) |
| β_KL | 0.0(off — RAM intrinsic anchor in target,不需要额外 KL) |
| rollout_adapter | `default`(on-policy per RAM Alg 1) |
| Anchor t cycle | [1000, 750, 500, 250](DMD 4 anchor) |
| K_noisings × G_endpoints | 4 × 4 = inner_steps |
| lr | 3e-4 AdamW(跟 NFT 同) |

### 3.3 Result(JID 8978352)

**`RAM-v1`** in [§5 三张表](#5-三张固定表-base-第一行-anchor)。摘要:

| Acceptance criterion | 阈值 | RAM-v1 实测 | Pass |
|---|---|---|---|
| UCF motion_fidelity | ≥ BASE × 0.9 = 0.31 | 0.314 | ✓ |
| LOVEU motion_fidelity | ≥ BASE × 0.9 = 0.36 | 0.357 | ✓ |

`Quality` 高过 BASE 是惊喜 — fast-adaptation 不仅没破质量,在某个维度还有提升。

### 3.4 跟 NFT 家族对比

| | NFT 最好 (H1) | RAM-v1 | BASE |
|---|---:|---:|---:|
| UCF mf | 0.12 | **0.31** | 0.35 |

## 4. DRaFT-K — memory wall,弃(详记录留作 lessons)

### 4.1 Motivation

RAM 用 scalar reward — group-normalized 后的 r ∈ [0,1] 作为 target shift coefficient,没经过 reward model 的 backprop。但我们的 `motion_fidelity`(CoTracker3 tracklets → cosine)在算法上**端到端可微**。DRaFT(Clark et al., arXiv:2309.17400)的核心 idea 就是直接把 reward 当 loss,梯度穿过 sampler + VAE + reward model。理论上 reward gradient 比 scalar reward 信号强。

设计 spec / 实施 plan 已 committed:
- [`docs/superpowers/specs/2026-05-22-draft-k-design.md`](superpowers/specs/2026-05-22-draft-k-design.md)
- [`docs/superpowers/plans/2026-05-22-draft-k-implementation.md`](superpowers/plans/2026-05-22-draft-k-implementation.md)

### 4.2 5 次 smoke 撞墙

| JID | 配置 | 结果 |
|---|---|---|
| 8985536 | K_grad=1, K_rollouts=1, H200 | OOM at VAE decode, peak 137.6 GiB |
| 8987002 | + cache-free fix + outer VAE ckpt | OOM, peak 137.2 GiB(outer ckpt 只省 0.4 GiB) |
| 8988734 | + cache-disabled per-frame VAE ckpt | **OOM 解了,但发现 cache=None 跳过 temporal upsample,输出 21 frame ≠ expected 81** → cancel |
| 8989380 | + cache-preserving per-frame VAE ckpt | OOM 解,但 `CheckpointError: shape [18720, 12, 128] vs [14040, 12, 128]` — generator 的 KV cache 在 7 个 grad-on forwards 间 in-place mutated,gen ckpt replay state mismatch |
| 8989490 | + disable generator gradient checkpointing | H100 80GB OOM, peak 79.15 GiB(无 gen ckpt = 7 grad-on forwards 全活在显存) |

### 4.3 架构诊断

DRaFT 原 paper 是 **single-frame image diffusion**:
- 单帧 image → 单次 sampler forward → 单次 VAE decode
- 没有 KV cache 跨 block mutation,gradient_checkpointing 直接套上工作

我们的 setup:
- 21-frame latent → 81-frame pixel VAE(per-frame decoder for-loop,内部累积 21 帧 activations)
- 7 causal blocks × 4 DMD steps = 28 generator forwards per rollout
- KV cache(`cache["k"][:, ...] = new_k`)在 7 个 grad-on forwards 间 in-place mutated
- gen ckpt 的 backward replay 看到的是**所有 7 个 forward 写完之后的 cache 终态**,不是 iter-time 的 cache 状态 → shape mismatch

要让 gen ckpt 正确工作必须 snapshot KV cache state at each call,但 snapshot 成本 = ~14 GiB / call × 7 calls ≈ **98 GiB**,比 activation 本身还贵。架构性 mismatch,不是 implementation bug。

### 4.4 Memory budget

| 配置 | 估算 | 容器 |
|---|---:|---|
| K_grad=1, K_rollouts=1 (smoke) | ~79 GiB | H200 ✓ / H100 ✗ |
| K_grad=1, K_rollouts=2 | ~125 GiB | H200 ⚠️ 紧 |
| **K_grad=2, K_rollouts=2 (spec full)** | **~150 GiB** | **超 H200 ✗** |

也就是说,即使我们让 smoke 跑通,**spec'd full 配置 fundamentally fits 不下 H200**。要跑必须降回 K_grad=1 / K_rollouts=1 — 这削弱了 DRaFT 的核心 idea(更多 grad steps + 更多 rollouts 让 reward gradient 信号显著)。

### 4.6 Lessons

- DRaFT-class methods 在 video DMD 上的 memory cost 不是 implementation bug,是架构性 mismatch
- 要让 DRaFT 工作必须改设计:
  1. 降 resolution / frame_count(但 break eval protocol 一致性)
  2. OR latent-space reward(skip VAE in grad path,另起炉灶训 latent → tracklets 的 proxy)
- 两条都已经偏离 DRaFT 原 design,等于换方法,不在 v1 范围

## 6. 结论与下一步

### 6.1 当前主线

**RAM-v1 是 working fast-adaptation baseline**。runtime ~50 min on 8 H200(20 outer × 16 inner × K=4),输出 rank-32 LoRA 直接挂 `longlive_base.pt`。VBench Total 持平 BASE,Quality 略胜 BASE,UCF / LOVEU motion_fidelity 都 ≥ BASE × 0.9。

### 6.2 待考虑的 follow-up(无优先级,看产品需求)

- **reward_coef sweep**: RAM paper §D 在 binary partial-credit reward 上用 100 / 1000。我们 continuous in [-1, 1] 起 1.0。10× / 100× 是否进一步提 mf?可能,但 reward 信号过强也可能 break Quality(目前 Quality 84.86 是惊喜,值得保护)。
- **β_KL ablation**: 当前 0(off)。RAM intrinsic anchor 已经 in target;加 1e-3 显式 KL 是否帮 safer landing,还是 over-constrain?
- **不同 reference clip 的 RAM 复现性**: 目前只在 UCF Skateboarding 上验过。换 Diving / Lifting 是否稳定?

### 6.3 不再深追

- NFT family:阶梯走完,定论 β-interp + EMA self-mirror 在 4-step DMD video 上 fundamentally limited。除非换 loss form,否则不再调参。
- DRaFT-class methods:21-frame causal video DMD 跟 single-frame image DRaFT 是架构性 mismatch。要碰 DRaFT 必须先解决 latent-space reward 问题 — 那是另一篇 spec。
