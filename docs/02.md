## 关键概念区分

### MLE vs reverse-KL — 这是 MotionDirector 跟 DMD 的本质差别

- **MotionDirector** 的训练目标 `‖ε_θ(x_t, t) − ε‖²`(标准 DDPM denoising MSE)是数据对数似然的 variational lower bound,本质 = **在 reference 上做 MLE = forward KL** `D_KL(p̂_data ‖ p_θ)`
- **DMD** 的 generator 梯度 `E[(s_fake − s_real) · ∇_θ x]` 是 **reverse KL** `D_KL(p_θ ‖ p_teacher)` 的 reparameterization 梯度
- **后果**:
  - MLE 是"加法":data 在哪就把概率推到哪,可以教 base model 完全不会的概念(reference video 里有就能学)
  - reverse-KL 是"对齐":student capability ≤ teacher capability,teacher 不会的事情 student 学不出来

### 为什么 forward KL 对 diffusion 不可行(选 reverse KL 不是哲学偏好,是物理事实)

- forward KL 的 gradient `∇_θ D_KL(p_teacher ‖ p_θ) = −E[∂_θ log p_θ(x)]` 需要 **student log-density 自身**,而非 score
- diffusion 的 native output 是 **score**(ε_θ / v_θ),log-density 不是 native——要靠 PF-ODE 沿 score 积分 + Hutchinson trace estimator 凑出来(`log p_θ(x_0) = log p_T(x_T) + ∫ tr(∂v_θ/∂x) dt`)
- 单次评估 ~50 ODE steps × ~4 Hutchinson samples = O(几百次)模型调用;训练还要对这条积分链路反向 → nested differentiation,显存 + 工程双爆
- reverse KL 的 gradient 通过 reparameterization + score-function identity 化简成 **`(s_θ − s_teacher) · ∇_θ x`**,只调用 score(native output),一次 forward 出梯度
- 这是 **diffusion + forward KL 这个特定组合不兼容**,不是 KL 本身的问题:normalizing flow 的 log-density 是 native output,forward KL 立刻可行

### MotionDirector 实际工作方式(2026-05-12 二次读 code/paper 校正)

- **reference video = 含目标 motion 的视频**,subject **不需要**跟推理目标一致
  - cat-dunk 用例:reference = 真人扣篮视频
- 训练数据 = `(x_t = α_t·x_0 + σ_t·ε, x_0_reference)`,标准 DDPM 自监督
- **核心 mechanism = appearance-debias 损失项**(`MotionDirector_train.py:872-878`),不是 inference 端的 scale knob:
  ```
  β=1, α=√2; ran_idx = 随机帧
  pred_decent   = α·pred   − β·pred[:, :, ran_idx, :, :]
  target_decent = α·target − β·target[:, :, ran_idx, :, :]
  loss_AD       = MSE(pred_decent, target_decent)
  loss_total    = loss_temporal_MSE + loss_AD + loss_spatial   # 三项等权
  ```
  减完锚帧后跨时间共享分量(= 外观)消掉,只剩 frame-to-frame 残差(= motion)
- **dual-LoRA 实现**:spatial LoRA on `Transformer2DModel`(吸 single-frame appearance);temporal LoRA on `TransformerTemporalModel`(吸 motion)。rank 32, dropout 0.1
- **推理形态(纠正之前的误读):没有 `spatial_scale=0` 这个 API**:
  - 单脚本 `MotionDirector_inference.py` 根本不挂 spatial LoRA,只挂 temporal LoRA + DDIM 30 步 + CFG 12 + 可选 `noise_prior=0.1~0.5`(DDIM 反演 reference clip 做 latent prior)
  - 多脚本 `MotionDirector_inference_multi.py` 是把 spatial LoRA 指向**另一个 image domain 的 LoRA**(如 Terracotta-Warrior 图)做风格 swap,不是 disable donor 外观
- **训练规模**:16-frame × 384² × fp16 × LR 5e-4 × AdamW × 300–3000 steps × batch 1 — 资源需求极低

## MotionDirector → LongLive 的实际障碍(2026-05-12 重评估)

之前列的"四条"里有两条在 code 细读后实际不成立。重新整理:

| 维度 | 障碍 / 解决方式 |
|---|---|
| **架构** | dual-LoRA 依赖 `Transformer2DModel` / `TransformerTemporalModel` 物理分离;Wan DiT 用 3D self-attn 把 (space × time) tokens 一起算,无此干净二分。**解决**:agent 2 给出的答案是**丢掉 spatial 分支,Wan 上单 LoRA 挂所有 attn Q/K/V/out + FFN,只保留 `L_temporal_MSE + L_AD`**。debias 项本身就承载了 motion-vs-appearance 解耦的全部 mechanism,spatial 分支只是 content quality 二级 trick。**单 LoRA + debias 是架构无关的,可移植** |
| **训练范式** | DMD 没有 supervised denoising 头,无法直接接收 reference 的 MSE 监督。**解决**:不是直接在 DMD generator 上加 MSE,而是 **MotionDirector recipe 跑在 teacher 上**(real_score = Wan-14B + motion-LoRA),DMD loop 不动,student 通过反向 KL 收紧到 motion-aware teacher |
| **步数失配** | MotionDirector LoRA 在 30-step DDIM 上训,LongLive student 在 4 个离散 t 上做大 jump。**实际不冲突**:若 motion-LoRA 训在 teacher 上(teacher 本身就是 30-step+ DDPM/FM regime),student 通过 distillation 处理 step 压缩,两边 t 范围互不干扰 |
| **管线缺失** | DMD trainer 没有 "reference clip → MSE supervision" 这条路径。**解决**:不需要进 DMD trainer。新建独立的 teacher motion-finetune 脚本,产物是一个 motion-aware Wan-14B 检查点;再用现有 DMD trainer 加载这个 ckpt 做 student distillation |

**修订结论**:之前说"等同新工作量"过于悲观。实际可行实现:**单 LoRA on Wan teacher + appearance-debias loss + 独立 finetune 脚本**,不动 DMD 三件套,不动 generator。

## 三条可行路径

### A. 当前状态:LoRA on DMD
- 已落地(`adapter.type: lora, rank: 256` + OFT 变体)
- ✓ Few-step
- ✗ 不能超越 teacher 分布(reverse-KL 上限)
- 改动:零

### B. MotionDirector on teacher → DMD distill student(2026-05-12 修订后的首选)
- 步骤:
  1. 独立 MotionDirector finetune Wan-14B teacher(单 LoRA + appearance-debias + 标准 DDPM MSE)→ motion-aware teacher
  2. 用这个 motion-aware teacher 当 `real_score`,跑现有 DMD distillation → student 通过反向 KL 收紧到含 motion 的 teacher
- ✓ 能超原 teacher 分布(因为有 MLE 监督进了 teacher 上游)
- ✓ 不违反 `dmd_architecture_frozen`(DMD 三件套结构和 loop 都不动,只是 real_score checkpoint 换了)
- ✓ student few-step 由 DMD 保证
- ✗ 每个新 motion 概念都需要一次 teacher finetune + 一次 student redistillation
- ✗ Wan-14B 上的 LoRA 训练 + 后续蒸馏的两步流水线,资源时间双倍
- 改动:L0(reference 数据 pipeline,独立) + 一个 standalone teacher-finetune 脚本(不进 DMD trainer);DMD trainer 零修改

**旧 B 形态(在 generator 上加 MSE 头)被弃**:朴素加权 `α·∇_DMD + β·∇_MSE` 梯度方向天然冲突(DMD 说"贴 teacher",MSE 说"贴 reference"),过往 motion-DMD 已经在这个失败模式上踩过坑

### C. 换 Bridge 框架(DDBM / I²SB)
- target = Wan-14B 50-step 在 cat-dunk prompt 上合成(依赖 `project_teacher_boundary_2026_05_10.md` 已验证 14B 能产出 cat-dunk)
- source 选项:
  - DDBM 风:Wan-base / 1.3B 输出当 source,distribution pairing
  - I²SB 风:`x_source = noise_augmentation(x_target)`,自监督 pairing
- ✓ Few-step 原生:DBIM / CDBM 是 framework 自带,不需要外接蒸馏阶段
- ✓ DiT 兼容:架构无关,直接套 Wan
- ✗ 推理时必须给 source state(state-transformation,非 text-only)
- ✗ Video DiT 上无先例
- 改动:整个 trainer / sampler / model 三件套重写

## Bridge vs MotionDirector

| | MotionDirector | Bridge (DDBM / I²SB) |
|---|---|---|
| few-step | ✗ DDIM 30 步,要 few-step 需外接蒸馏 | ✓ DBIM / CDBM 原生 1–4 步 |
| 底层架构 | UNet 专用(Transformer2D/Temporal 二分) | 架构无关,DiT 直接适配 |
| 理论框架 | heuristic dual-LoRA + appearance-debias | Schrödinger Bridge / Doob's h-transform |
| 推理形态 | text-only(prompt → video) | 需 source state(source + prompt → video) |
| Motion vs Appearance 解耦 | ✓ 显式(dual-LoRA + debias) | ✗ 隐式(靠 source/target 选择) |
| 跟现代工具栈组合 | LoRA 可叠 OFT/DoRA,但 mechanism 孤立 | 可叠 DiffusionNFT / rCM / Geometry Forcing |
| 数据成本(cat-dunk) | 低(真人扣篮视频海量) | 中(target 要靠 14B teacher 合成) |
| Video DiT 工程风险 | 中(需重写 dual-LoRA mechanism) | 高(无先例) |

## 决策点

- ✅ MotionDirector 的 appearance-debias 损失项**架构无关、可移植**,2026-05-12 二次读 code 后从"不能搬"修订为"丢掉 spatial 分支后单 LoRA 即可移植"
- ✅ 路径 B(MotionDirector on teacher → DMD distill)是当前首选,不违反 `dmd_architecture_frozen`
- ✅ Bridge 是结构上最匹配 "few-step + 超 teacher 分布" 的框架,**但当前暂停**(2026-05-12 用户决策),先把 path B 跑通
- ✅ `dmd_architecture_frozen` 仅在 DMD 路线内适用;切换框架时自动失效(memory 已更新 scope)
- ⏳(Bridge 相关待定项暂搁置)

## 同时澄清的边界条件(为后续讨论)

1. **diffusion 的 native output 是 score / velocity,不是 log-density**——这一条决定了为什么 reverse KL 比 forward KL 在 diffusion 上工程可行
2. **DDPM 和 Flow Matching 都允许任意 ODE solver**;FM 的优势不是"变步长",而是 **linear path 曲率低**,均匀步长下数值误差更小
3. **score 和 velocity 是同一对象的不同参数化**(给定 noise schedule close-form 可换),只是哪个被网络直接输出不同;不是 diffusion vs FM 的区别
4. **ODE 和 SDE 在 marginal 分布上等价,单条 trajectory 上不同**——ODE 是 deterministic 1-to-1 映射(可逆、可蒸馏),SDE 是 stochastic 1-to-many。Video / world model 上几乎一定走 ODE
5. **高维 video latent 上 off-manifold 是个真实问题**(ambient ~2M dim,intrinsic 远小),autoregressive 复合会放大单步偏离 → 这也是 LongLive few-step deterministic 路线的另一个 motivation

## 不会再做的几件事(给自己设的护栏)

- **Motion-DMD 复活**:已删,论证机制(score-端 attn 注入)被 MotionDirector 的 anchor-frame 减法在 loss-端的解耦做法证伪过一次。不再回到 score-injection 这条路
- **在 DMD generator 上直接加 α·∇_DMD + β·∇_MSE 加权**:梯度方向冲突无法靠加权解决,过往 motion-DMD 已经在这个失败模式上踩过坑。注意:这一条约束 generator 端的 loss 叠加,不约束 teacher 端的独立 finetune
- **强行把 MotionDirector dual-LoRA 物理结构搬到 Wan DiT**:架构上没有 Transformer2D/Temporal 二分,prefer "单 LoRA + debias only" 的简化版本(agent 2 推荐方案)
