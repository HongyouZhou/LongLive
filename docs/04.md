## 1. 决策一句话

跟 4 小时 MSE finetune 比,**DiffusionNFT 的 forward-process self-rollout loss 在结构上避开两类 MSE 失败模式,且 paper-claim 25× faster**(虽然 25× 不会原样迁移到 video)。在 NVlabs DMD base 上加一个 rank-32 LoRA,K=4 自采样,motion_fidelity 当 reward,**target: motion_fidelity > BASE 0.354,wall-clock ≤ 30 min**。

## 2. Paper deep-read 摘要

读完四篇,各自结论:

| Paper | 是否采纳 | 一句话 |
|---|---|---|
| **DiffusionNFT** (arxiv:2509.16117, ICLR 2026 Oral, Apache-2.0) | **采用** | forward-process FM loss + dual-adapter + group-norm scalar reward |
| **Flash-GRPO** (arxiv:2605.15980, ICML 2026) | 弃 | iso-t/TGR 两 trick 在 4-step 上几乎失效(λ 只 2× variation);repo motion reward 缺失;TGR `value_dict` hardcode UniPC |
| **Flash-DMD** (arxiv:2511.20549) | 弃 | image only,要训 Latent Reward Model + SAM discriminator,组件太多 |
| **On-Policy Distillation** (Thinking Machines, Oct 2025) | concept-only | LLM token-level,纯 framing 输入("dense > sparse"),不直接迁移 diffusion |

### 2.1 Flash-GRPO 为什么不选

- TGR 设计的 motivation 是"λ(t) varies orders of magnitude",但 code 实测训练用的 10 个 t 上 λ 只在 3.78–7.48 范围(2× variation),order-of-magnitude 区间被它自己 `weights=[1]*10 # only first 10 steps` 排除。
- λ 公式假设 Euler-Maruyama small-Δt 极限,在 4-step DMD(Δt = T/4)上偏离更远;DMD-distilled student 的单步过渡分布也不一定是 Gaussian-around-Euler。
- Iso-temporal grouping 在 4 个 t bucket 上 marginal value 比 10 bucket 小很多。
- Repo:`flow_grpo.diffusers_patch.wan_prompt_embedding` 缺文件;`app_videoalign` 仅注释提到无实现;hardcoded reward IP;没 LICENSE;known bug workaround `if epoch < 2: continue`。
- **Code 里实际 reward 只有 HPSv3(image-quality preference),跟 motion 无关**。Paper 的"VideoAlign motion score"在 code 中不存在。

### 2.2 DiffusionNFT 为什么选

- Apache-2.0,857 stars,run-as-published(只是 torch 版本不对齐我们)。
- Paper 提的"25× faster"虽然不会原样迁移,**5 个机制核心都是结构性的、不依赖 image-domain 假设**:
  1. Forward-process loss(skip backprop through sampling chain)
  2. Dual-adapter `default` / `old`(避开 `disable_adapter() × FSDP` 兼容 bug)
  3. Group-normalized scalar reward
  4. β-interp ±contrastive(可选,可降级)
  5. Soft-EMA refresh
- Eq.(5)对 velocity-FM 通用,**4-step DMD student 仍是 velocity 预测器**,数学上 type-check 通过。
- 风险已知:Issue #46(velocity collapse on heavily-constrained network)、Issue #2(video unverified,closed unanswered)。

## 3. 采纳的核心机制

### 3.1 Loss

NFT Eq.(5)(verbatim from arxiv:2509.16117):

```
L(θ) = E_{c, x_0 ~ π^old, t, ε} [ r · ‖v_θ^+(x_t, c, t) − v‖²  +  (1 − r) · ‖v_θ^-(x_t, c, t) − v‖² ]
```

implicit parameterization:

```
v_θ^+ = (1 − β) · v^old + β · v_θ
v_θ^- = (1 + β) · v^old − β · v_θ
```

with `x_t = (1−σ_t) · x_0 + σ_t · ε`,`v = ε − x_0`(rectified-flow convention,跟我们 `FlowMatchScheduler` 一致)。

**β=1.0 起步**:
- `v_θ^+ = v_θ` → 正分支 = 标准 FM(高 r 样本 → 拉 v_θ 朝它走)
- `v_θ^- = 2 v^old − v_θ` → 负分支 = mirror(低 r 样本 → 反向推)
- 两分支之间无混合,Issue #46 触发面最小。崩了再降 0.1。

### 3.2 x0-domain adaptive weighting(NFT code 实际形式)

NFT code 没直接用 v-space MSE,改用 x0-domain + per-sample 自归一(NFT `train_nft_sd3.py:940-960`):

```python
x0_pos = x_t − σ_t · v_pos
weight = stop_grad |x0_pos − x_0|.mean()  # detached L1 per sample
positive_loss = ((x0_pos − x_0)² / weight).mean()
# 同样的 x0_neg → negative_loss
loss = (r · positive_loss + (1 − r) · negative_loss) / β · adv_clip_max
```

我们沿用此形式 —— x0-domain 在我们 `WanDiffusionWrapper` 是 native output(`forward → (flow_pred, pred_x0)`),不用额外推导。

### 3.3 KL anchor(NFT code 内置,paper Eq.5 没写)

```python
kl_loss = ((v_θ − v_ref) ** 2).mean()
total = policy_loss + β_KL · kl_loss     # β_KL = 1e-4
```

`v_ref` = base 无 LoRA 输出。**实现走 NFT 的 dual-adapter 模式**:不用 `disable_adapter()`(我们已知 `disable_adapter × FSDP × gradient_checkpointing` 崩,run 8939766),改用第二个 zero-init 不训的 adapter。

### 3.4 Dual-adapter `default` / `old`

```python
transformer = get_peft_model(transformer, lora_config)  # adapter "default"
transformer.add_adapter("old", lora_config)             # 同 config
# rollout: set_adapter("old"), no_grad
# train:   set_adapter("default"), grad
# epoch 末: old ← decay · old + (1 − decay) · default
```

`decay = min(0.001 · global_step, 0.5)` —— NFT 默认 ramp。前期 v^old ≈ v_θ(快),后期 v^old 滞后(稳)。

### 3.5 Group normalization

K=4 个同 caption 同 ref 的 rollout,reward = motion_fidelity score(scalar)。

```python
# 4 个 rewards 组内 z-norm
mean = rewards.mean()
std = rewards.std() + 1e-4
advantages = (rewards − mean) / std
advantages = advantages.clip(−adv_clip_max, +adv_clip_max)
r = 0.5 + 0.5 · (advantages / adv_clip_max)   # → [0, 1]
```

## 4. 跟我们 setting 的关键不对齐

| NFT 假设 | 我们的现实 | 应对 |
|---|---|---|
| Multi-step ODE rollout(10–25 NFE) | 4-step DMD,> 4 步质量反崩 | **Rollout 锁 4 步** |
| 训练 t = rollout 的 10 个 timestep,not uniform [0,1] | DMD 只在 4 个 anchor 训过 | **训练 t 锁在 4 anchor**,不喂 off-DMD 信号 |
| Scalar reward r ∈ [0,1],black-box,not differentiable | motion_fidelity 本身可微,但运行时算分用 CoTracker(慢) | **当 black-box scalar 用**,不利用可微性。如要 hybrid OPD-style 见 §8.2 |
| K=24 per prompt | rollout ~30s × K=4 = 2 min outer iter | **K=4**,global_std=True 跨 K 维度 std |
| LoRA r=32 alpha=64 on SD3.5M | 我们 base 是 DMD 蒸馏过的 Wan-1.3B | **r=32/α=64** — product-driven(runtime 必须小 rank) |
| Image-domain reward(HPS/PickScore/CLIP) | motion_fidelity on video | reward 换 motion_fidelity,reward → r 的 group-norm 流程不变 |

**Note**:NFT paper / code 没在 few-step generator / video 上验过(Issue #2 closed 无回应)。我们是首次。

### 6.2 各文件职责

**`rollout.py`** — 接 `longlive.pipeline.CausalInferencePipeline.inference`,加 `set_adapter("old")` 切换,fix seed,返回 `(video, latent_x0)`。验证 4-step rollout 跟 BASE 推理 byte-for-byte 一致(或 ε-level 一致)。

**`reward.py`** — wrap `scripts/motion_eval/metrics/motion_fidelity.py`:
- 入口:`(generated_video_path, ref_video_path) → scalar`
- Reference tracklets 启动时计算一次,cache 到内存
- 每次 rollout 调用:VAE 已经 decode 过(rollout 顺手),CoTracker forward(~5s)+ cosine sim

**`losses.py`** — 两函数:
- `nft_policy_loss(flow_pred_default, flow_pred_old, pred_x0_default, pred_x0_old, x0_ref, sigma, r, beta, adv_clip_max)` —— NFT Eq.5 + x0-domain adaptive weight
- `kl_anchor_loss(flow_pred_default, flow_pred_anchor)` —— `(v − v_ref)²` MSE

**`stat_tracking.py`** — port `PerPromptStatTracker`,single-prompt 简化:K 个 reward → z-norm → clip → r ∈ [0,1]。~50 LOC。

**`train.py`** — 主训练 loop:
```
for outer_epoch in range(20):
    # ===== ROLLOUT (no_grad) =====
    generator.set_adapter("old")
    rollouts = []
    for k in range(4):
        with no_grad:
            video_k, x0_k = pipeline.inference(noise=seed_k, caption=train_caption)
        r_raw_k = reward.motion_fidelity(video_k, ref_path)
        rollouts.append((video_k, x0_k, r_raw_k))

    # ===== GROUP NORM =====
    r_list = stat_tracking.group_normalize([r for _,_,r in rollouts])

    # ===== TRAIN (grad) =====
    generator.set_adapter("default")
    for inner in range(16):
        rollout_k, t_k = sample_inner_batch(rollouts, anchor_ts)
        # forward-noise x0_k at t_k
        # v_default = generator(x_t, c, t_k)          [grad]
        # v_old     = generator_set_adapter("old")(x_t, c, t_k)  [no_grad]
        # v_anchor  = generator_set_adapter("anchor")(x_t, c, t_k)  [no_grad]  # zero LoRA = base
        # loss = nft_policy_loss(...) + 1e-4 · kl_anchor_loss(v_default, v_anchor)
        loss.backward(); optimizer.step()

    # ===== EMA REFRESH v^old =====
    decay = min(0.001 * global_step, 0.5)
    for src, tgt in zip(default_params, old_params):
        tgt.data.copy_(tgt.data * decay + src.data * (1 − decay))

    # ===== SMOOTHNESS LOG (inline diagnostic) =====
    # 每 epoch 末 log ‖x0_default − x0_ref‖, ‖x0_pos − x0_ref‖, ‖x0_neg − x0_ref‖
    # 若 neg 量级 > 5× default,触发警告并降 β
```

| Step | 文件 | 时间 | 验收 |

| 1 | `rollout.py` | 1d | 4-step rollout 跟 BASE 推理一致(fix seed) |

### 6.4 Smoke 通过判据(step 5–6)

- `nft_policy_loss` 初值 ~O(1),5 步后下降(不 NaN 不爆)
- `kl_anchor_loss` 初值 ~0(LoRA zero-init),稳步上升然后 plateau
- Dual-adapter `set_adapter("old") / set_adapter("default")` 在 FSDP-wrapped 模型上不报错
- Smoothness log:`‖x0_neg − x0_ref‖ / ‖x0_default − x0_ref‖ < 5×` —— 否则 β-interp 几何不可信,触发降 β 到 0.1
- 2 outer epoch GPU memory 不 OOM

## 8. Risks 与 open questions

### 8.1 Issue #46 — velocity collapse on constrained network

NFT GitHub 上 community 报的:LoRA 较小时,`v_θ^+ − v_θ^- → 0`,正负分支无效,reward signal 消失,maintainer 无回应。

**应对**:
- β=1.0 起(正分支无混合,不依赖 ±β 几何对称)
- smoothness log inline,触发 → 降 β
- 极端情况:`positive_only RFT`(loss = `r · ‖v_θ − v‖²`,扔掉负分支)

### 8.2 motion_fidelity 是 scalar reduction,丢 dense 信号

CoTracker tracklet cosine 是 per-clip scalar。dense 的 per-track / per-frame 差异 collapse 到一个数,group-norm 只能看"哪个 rollout 整体更好"。

**应对**:
- 先 baseline。如果 NFT scalar 路线 mf 上不去,后续可考虑 hybrid:用可微 motion-distance 在 x_0 上构造 dense target(本质是 motion-shifted FM regression,不是 NFT),作为 follow-up,不进 v1。

### 8.3 K=4 group size 偏小,reward std 噪

NFT image 用 K=24,我们 K=4 group-norm 信号不稳。

**应对**:
- global_std=True(跨多 outer epoch 累积 std)
- 早期 epoch 加大 EMA decay(快滚 v^old)平滑 reward 分布

### 8.4 Off-DMD t 不喂训练信号 = 自我约束

我们锁训练 t 在 4 anchor。但 forward 过的 x_t 是任意 σ 的(rollout 路径上的 4 个),理论上 t = anchor 时严格满足。

**应对**:验证 rollout 路径生成的 x_t 总是落在 4 anchor 上(`FlowMatchScheduler` 的 4 个 sigma)。

### 8.5 Dual-adapter × FSDP × gradient_checkpointing

我们之前 `disable_adapter() × FSDP × gradient_checkpointing` 崩(run 8939766)。NFT 用的是 dual-adapter `set_adapter` 切换,**不同 PEFT 路径**,但底层都动 `module._active_adapter`。**未在我们 codebase 验过**。

**应对**:step 5 第一件事就是 dual-adapter × FSDP × gradient_checkpointing smoke(50 LOC,~1h)。失败 → debug PEFT internals 或者关 gradient_checkpointing 看代价。

### 8.6 Wall-clock 估算可能乐观

K=4 rollout 估 30s 每个 = 2 min。但 motion_fidelity reward 包含 CoTracker forward,~5–10s 每个,总 outer rollout = 4 × (30s gen + 7s reward) ≈ 2.5 min。Inner 16 step,每步要 forward `default` + `old` + `anchor` 三套,~3s × 16 ≈ 50s。Outer 共 ~3 min。20 epoch ≈ 60 min。

**比 30 min 估算多一倍**。需要在 smoke 后实测,可能要:
- 降 inner 到 8
- 降 outer cap 到 10
- 加 inference compile 优化
