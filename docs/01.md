# 01 — Idea 模块化:按"扰动层"切分

LongLive 的 `longlive/methods/<idea>/` 接纳的 idea 数量会随时间增长(Bridge、OFT、未来的 NFT 变体、sparse-attn 等)。为避免每个 idea 重新发明 trainer / config / 注册逻辑,把 diffusion 训练 pipeline 拆成 **6 个扰动层**,每个 idea 显式声明自己触碰哪几层,只通过该层已有的 seam 注入。

## 抽象层级

| 层 | 内容 | 已有 seam | 当前位置 | 例子 idea |
|---|---|---|---|---|
| **L0 数据** | 配对 / 无配对 / 参考样本采样 | dataset 类 | `longlive/utils/dataset.py` | 数据挖掘、ref 选择策略 |
| **L1 参数化** | 可训练参数怎么挂到冻结主干 | adapter dispatch | `longlive/utils/lora_utils.py` + YAML `adapter.type` | **OFT** / DoRA / SVDiff |
| **L2 前向 hook** | 运行时改 attn / FFN 张量 | hook injector | (待添加) | sparse-attn / 注入式 idea |
| **L3 教师 score** | 蒸馏的目标信号怎么算 | 子类 DMD | `longlive/model/dmd.py:_compute_kl_grad*` | **Bridge** / NFT |
| **L4 损失形式** | 学生 vs 目标怎么比 | DenoisingLoss 插件 | `longlive/utils/loss.py:NAME_TO_CLASS` | flow / consistency / Bridge residual |
| **L5 训练循环** | 阶段顺序 / 何时切换什么 | 子类 trainer | `longlive/trainer/ScoreDistillationTrainer` | 多阶段调度(罕见) |

## 设计纪律

- **新 idea 不能新增层。** 要新增层意味着已有抽象 leaks,先讨论再写代码。
- **每个 idea 声明自己触碰哪几层。** 写在 `longlive/methods/<idea>/README.md` 第一段。设计审查 = 检查这个声明是否最小、是否准确。
- **idea 之间正交是好信号。** 两个 idea 投影到不同层 → 可同时启用,组合不需要互相知道对方存在。

## 已有 idea 的层投影

- **Bridge**(规划中):**Schrödinger Bridge** 框架。student 不从纯噪声起步,从 source video latent(加微噪)起步沿 bridge SDE 反向到 target。**学的是 source→target transformation,推理时必须输入 source state**(详见下方"reference-internalize vs state-transformation"段)。
  - 触碰层:**L1**(student input 加 source conditioning,改 `WanDiffusionWrapper` 接收 source latent)+ **L3**(替换 score 计算,bridge score / velocity 不是 marginal score)+ **L5**(替换 trainer 训练循环,bridge loss 不是 DMD KL surrogate)+ **L0**(paired (x_source, x_target) 数据 pipeline)
  - 框架候选:**DDBM**(canonical SB,Doob's h-transform,通用)/ I²SB(Gaussian posterior,简单)/ BBDM(Brownian bridge,velocity-like prediction,跟 Wan flow-matching head 最贴)
  - 当前倾向 **DDBM** —— 1.3B 视频上无先例,理论 generality 高,phase-1 不需要原创蒸馏方法(40 NFE 直接当 teacher);phase-2 蒸馏可套用 DBIM/CDBM 现成方案
  - **paired 数据必需**(SB 框架硬要求),walking 阶段倾向 B2(Wan-base 合成 x_source + 真实 walking clip 当 x_target);cat 扣篮阶段全合成
  - 推理路径与 LongLive 默认 causal pipeline 完全不同:`x_T = α_T·x_source + σ_T·ε` 起步,沿 bridge SDE 反向。新建独立 sampler,不复用 `causal_inference.py`
  - 跟 OFT(L1 adapter)正交,可叠加
- **OFT**(已落地):仅 L1。`longlive/methods/oft/__init__.py` 把 PEFT 0.19+ 的 `peft.OFTConfig`(块 Cayley + Neumann 近似 + init=I)注册到 `longlive.utils.lora_utils._ADAPTER_REGISTRY`。`oft_block_size=64` 起步;走和 LoRA 共享的 PEFT 路径(`get_peft_model` / state dict / `merge_and_unload`)。无自建 OFTLinear。DMD / loss / trainer 零变更,YAML adapter 段切 `type: "oft"` 即生效。
- **Adaptive timestep**(候选,未规划):L5(把固定 `denoising_step_list` 替换为动态调度)+ 可选 L3(score target 端 t 的选取)+ 可选 L0(per-sample t 来自数据 / 任务难度)。形态多样:**(a) per-sample**——按 sample 难度决定从哪个 t 起步;**(b) per-region / per-token**——同一帧静态背景大 t 粗去噪、运动主体小 t 精去噪,空间非均匀;**(c) per-step in inference**——few-step 推理时 student 自选下一步 t,类比 implicit step-size control;**(d) curriculum on t**——训练初期偏好特定 t 段,后期均匀。与 Bridge 框架天然互补:Bridge trajectory 已被 source/target 锚定,中间 t 可任意切入,**adaptive t × Bridge 正交可叠**。也与 OFT (L1) 正交。

Bridge 与 OFT 完全正交 → 同一 YAML 可同时配 `adapter.type: oft` + `distribution_loss: bridge_dmd`。

## Reference-internalize vs state-transformation

做"特定主题 / 类别学习"有两条本质不同的路线,选哪条决定一切下游:

**Reference-internalize(DreamBooth / LoRA fine-tune / D-OPSD 这一族)**

- 用一个 reference(image / video / paired data)在训练期改造 teacher 信号或直接 fine-tune,把 reference 蕴含的概念**蒸进 student 权重**
- 推理时 reference 不再需要,student 接受 text-only 输入,生成出"看起来包含那个 reference 概念"的样本
- 学的是"记住":特定 prompt 触发特定输出

**State-transformation(Bridge / SB / DDBM 这一族)**

- 学的是从一个**状态分布**到另一个**状态分布**的映射
- 推理时**用户必须提供 source state**(source video latent),模型把它沿 bridge 转换到 target 分布
- 学的是"转换":同一模型适用任意符合 source 分布的输入
- Bridge 走这条

**判别**:推理时是否需要用户提供 source 是判定属于哪族的唯一标准。这两族不是 alternative,是不同产品。

## 注册方式:启动时自动扫描 + side-effect 注册

约定:

1. core 注册表(`NAME_TO_CLASS`、adapter dispatch、`distribution_loss` 分发)保持现状,不感知 idea 存在。
2. trainer 启动时一次性扫描 `longlive/methods/*/` 全部 import(`pkgutil.iter_modules` 或显式遍历),让每个 method 的 `__init__.py` 跑一遍。
3. 每个 `longlive/methods/<idea>/__init__.py` 用 side-effect 把自己注册到 core 表里。
4. YAML 选哪个 active 仍由 `adapter.type` / `distribution_loss` / 等具体字段决定;扫描只是把候选都加载进注册表。

效果:加一个 idea = 新建一个目录;无需动 YAML、core、trainer 任何配置或代码。

**`__init__.py` 纪律(强制)**:只允许 (a) `from .X import Y` 形式的相对 import、(b) `register_*(...)` 注册调用。**不允许任何 heavy module-level 代码** —— 不 instantiate model、不 `torch.compile`、不读盘、不分配显存。否则所有 run 启动时都为这个 idea 付代价,与"未启用 = 零开销"的承诺破坏。

**键冲突**:注册函数发现 key 已存在 → raise,不静默覆盖。

**性能影响**:训练时零开销(未 active 的 method 代码永远不调用)。启动时多 import 几个轻量 module 是 ms 级,跟 FSDP wrap + 14B teacher load 比可忽略。CPU 内存 +几十 MB 可忽略,GPU 零。

## `longlive/methods/<idea>/` 文件骨架

```
longlive/methods/bridge/
  __init__.py            # register bridge framework into core (trainer/sampler/loss)
  README.md              # 一段话:touches L0 + L1 + L3 + L5,framework=DDBM,why this cut
  source_conditioning.py # student input wrapper:接受 (x_t, t, source_latent, prompt)
  bridge_loss.py         # DDBM denoising bridge score-matching loss
  bridge_sampler.py      # 反向 bridge SDE solver(Heun + churn 或 closed-form)
  bridge_trainer.py      # subclass ScoreDistillationTrainer / 或新写 BridgeTrainer
  paired_dataset.py      # 加载 (x_source, x_target) 对,可能用 ref-style VAE 预 cache
  configs/walking_bridge_v1.yaml  # phase-1 walking 实验,完整 copy + override base config
longlive/methods/oft/
  __init__.py            # register adapter type "oft"
  adapter.py             # 正交参数化、attach
  configs/cat_dunk_oft_v1.yaml
```

L0 / L2 / L5 的文件只在真要用时再开,不预留空目录。

## YAML 写全,不做继承

每个 method config(如 `longlive/methods/bridge/configs/cat_dunk_v1.yaml`)是基线 config(如 `configs/default_config.yaml` 或现有 method config)的完整 copy + override,**不引入 `_base_:` 继承机制**。trainer 入口零特殊逻辑。代价:method config 跟基线 config 漂移时要手动同步 —— 接受这个成本以换取 trainer / OmegaConf 路径的简单性。

## 决策点

- ✅ **注册机制**:启动时自动扫描 `longlive/methods/*/`(`__init__.py` 纪律守住,效率不是问题,见上一节)。
- ✅ **YAML 继承**:不做,每个 method config 写全。
- ✅ **Bridge 路线**:state-transformation(SB),不是 reference-internalize。推理需要 source 输入。
- ✅ **Bridge 数学框架(初定)**:DDBM 主路,理论 generality + 1.3B 视频无先例 + phase-2 蒸馏有 DBIM/CDBM 现成方案。BBDM/I²SB 当 fallback,若 DDBM 实现遇阻可降级到 ViBT 风 BBDM-velocity-matching。
- ✅ **作废**:之前 "Δb_φ 由 LoRA 承载" 的判断错——Bridge 不是 score residual,是不同 SDE。
- ⏳ **Bridge phase-1 paired 数据来源**:walking 阶段 B2(Wan-base 合成 x_source + 真实 walking clip)主路,B3(HumanML3D 引入)备选。**待 OFT 跑完后规划 Bridge 实现时定。**
- ⏳ **Bridge 与 LongLive 现 trainer 的关系**:subclass `ScoreDistillationTrainer` 还是新写 `BridgeTrainer`?DMD 三网络 vs SB 单网络,差异较大,可能后者更干净。**待规划时定。**
