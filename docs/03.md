## CLIP-Text metric bug 诊断 + 修复

### 症状

第一次跑通的 baseline (`zorprn7j`):

```
loveu: n=304  app_div=0.6534  temp_consist=0.9704  pick_score=2.9952  motion_fidelity=0.3987
ucf:   n=60   app_div=1.6030  temp_consist=0.9728  pick_score=2.6200  motion_fidelity=0.3476
```

raw CLIP-L/14 logit(scale ≈ 100)对应 cosine 0.006 / 0.016。paper MotionDirector Table 1/2 报的 CLIP-Text ~23-28(cosine 0.23-0.28),差 15-20×。PickScore 同样异常低(2.6-3.0 vs 官方 19-22)。

### 诊断(`scripts/motion_eval/diag_clip.py`)

diff LOVEU 官方 `model(**inputs).logits_per_image.mean()` vs `CLIPMetrics.clip_score_text`:

- official = **22.749420**(cos 0.227)
- 我们的 manual reconstruction = **4.142737**(cos 0.041)
- delta = 18.6,5.5× off

逐层假设:

1. **split processor call(images-only + text-only)vs combined call**:`processor(text=..., images=...)` kwarg routing 差异?
   - 测试:换 combined call → 依然 4.14。**否定**。

2. **transformers v5 `get_image_features` 返回类型变了**:
   - 测试:✓ 返回 `BaseModelOutputWithPooling`(不是 v4 的 Tensor)
   - `.pooler_output` shape (17, **768**)— 已经是 projection_dim(NOT hidden_dim 1024),即已经过 `visual_projection`
   - `_embed_image` 的 fallback 链命中 `pooled.shape[-1] == proj.in_features` → False(768 != 1024)→ 跳过额外 projection → return `pooled`
   - deep diag 验证 `gif.pooler_output / norm` 跟 `out.image_embeds` delta = 5.9e-08(浮点精度等价)
   - **但 manual 仍然给 4.14**。说明 fallback 路径上还有 v5-specific 差异没暴露(可能 `vision_model` 在 `get_image_features` 上下文跟 `forward` 内部对 `pixel_values` 的处理路径不一样,具体在哪没追)

### 修复

放弃 `get_image_features` / `get_text_features`,直接走 `vision_model + visual_projection` / `text_model + text_projection`,复现 `CLIPModel.forward()` 内部 recipe:

```python
@staticmethod
def _embed_image(model, **inputs) -> torch.Tensor:
    pixel_values = inputs["pixel_values"]
    vision_out = model.vision_model(pixel_values=pixel_values)
    pooled = vision_out[1]  # pooler_output (raw, hidden_dim)
    return model.visual_projection(pooled)

@staticmethod
def _embed_text(model, **inputs) -> torch.Tensor:
    text_out = model.text_model(**inputs)
    pooled = text_out[1]
    return model.text_projection(pooled)
```

deep diag 的 `(C) visual_proj(vision)/norm` 路径已经验证 delta < 1e-7,unambiguous。

`clip_score_text` 用 `out.logits_per_image` 直接出数(LOVEU 官方写法)。`clip_score_frame` 和 `pick_score` 继承 `_embed_*` 的修。

### 验证

修后再跑 `diag_clip.py`:三个 manual 变体 + `CLIPMetrics.clip_score_text` 全部 = 22.749420,delta = 0.000000,`[verdict] IDENTICAL`。

## Baseline 数字(= reverse-KL ceiling)

`baseline_v1_fixed_8894159`(wandb run `vozg94rn`):LongLive 1.3B base ckpt × paper 协议:

| dataset | n | app_div | temp_consist | pick_score | motion_fidelity |
|---|---|---|---|---|---|
| LOVEU | 304 | **27.49** | 0.970 | **21.46** | 0.398 |
| UCF   | 60  | **25.61** | 0.973 | **21.00** | 0.348 |

参考量级:

- paper MotionDirector Table 1 (UCF) CLIP-Text 23-28 → 我们 25.61 落在区间内
- paper Table 2 (LOVEU) CLIP-Text 24-27 → 我们 27.49 略高(可能因为 LongLive base ckpt 在 LOVEU 这种偏 caption-driven 的 prompt 上对齐反而比 V2V edit 方法强)
- PickScore_v1 paper 报告 good-match 19-22 → 我们 21 ✓
- motion_fidelity 0.40 / 0.35 — 不直接 paper-comparable(LOVEU ref 是 source video,V2V benchmark 用 T2V baseline 跑;UCF prompt 是我们重建的)

结论:**LongLive 1.3B base ckpt 在 app_div / pick_score 维度已经接近 paper 顶部,reverse-KL ceiling 在 prompt-following 上不紧。motion_fidelity 0.35-0.40 才是真正待 push 的维度** —— 后续 motion-finetune 投入应该围绕 motion fidelity,不是 CLIP-Text。

## HPC 工作流补充

### `compute` vs `gpu` alias 对照

| alias | partition | GPU | CPU | mem | time | 用途 |
|---|---|---|---|---|---|---|
| `compute` | compute | none | 16 | 32G | 10h | CPU debug shell(数据 prep、CSV 处理、diag CPU 模式) |
| `gpu` | pgpu | 1 | 8 | 64G | 1h | GPU debug / diag CUDA 模式 / 单 ckpt smoke |

加到 HPC `~/.bashrc`:

```bash
alias gpu='srun -p pgpu --gres=gpu:1 --cpus-per-task=8 --mem=64G --time=01:00:00 --pty bash'
```

`compute` alias 已经在 [CLAUDE.md](../CLAUDE.md) "Pre-set in HPC ~/.bashrc" 表里。新增 `gpu` 也应该登录到那张表。

**注意**:pgpu 队列高峰排队长。debug 类工作如果 CPU 能跑就走 CPU。例 `diag_clip.py`:

```bash
# CPU mode, 1-2 min total (CLIP-L forward CPU on 17 frames + small overhead)
python scripts/motion_eval/diag_clip.py --device cpu --stride 5 --mp4 ... --prompt ...

# CUDA mode (in gpu shell)
python scripts/motion_eval/diag_clip.py --mp4 ... --prompt ...
```

按 [CLAUDE.md](../CLAUDE.md) "LongLive sbatch conventions",所有 SLURM 提交走 `source scripts/hpc/submit.sh`,**不要** bare `sbatch`:

### 已知坑点

- **transformers v5.6.2 vs v4 API drift**:`CLIPModel.get_image_features` / `get_text_features` 在 v5 返回 `BaseModelOutputWithPooling` 不是 Tensor。`.pooler_output` 已经是 projected (projection_dim) 不是 raw (hidden_dim)。任何 CLIP-style embedding 提取代码都应该走 `vision_model + visual_projection` 直接拼装,不依赖 `get_*_features`。
- **`lora_utils.configure_adapter_for_model` kwarg 改名**:`lora_config=` → `adapter_config=`(2026-05-12 提交)。`scripts/vbench/eval_worker.py` 和 `scripts/local/inference.py` 都跟着修了。
- **decord 跟 torch 2.8 cpp-extension 不兼容警告**:`Skipping import of cpp extensions due to incompatible torch version. Please upgrade to torch >= 2.11.0` — warning 而非 error,decord pure-Python 路径仍能读 mp4,忽略。
- **TLS 拦截代理 / 自签证书**:HPC `curl` 对外部部分 host(例 `www.crcv.ucf.edu`)cert 校验失败 → `prepare_motion_eval.py` 已经加 3-tier fallback(system CA → certifi bundle → `--insecure`)。
- **CoTracker3 自动下载**:`torch.hub` 拉 `facebook/cotracker3` zip + `scaled_offline.pth` (~97MB),需要 HPC login node 网络(compute node 出网受限,但 cache 后 compute 也能用)。首次 run 之前 frontend 跑一次。
- **40GB A100 排除**:`sbatch_motion_eval.sh` 默认 `--exclude=s-sc-dgx[01-02]`,8 worker × (CLIP-L + CLIP-H + CoTracker3 + Wan-1.3B + T5-XXL) 在 40GB 卡 OOM。pgpu 单 GPU debug 一般落在 H200 / 80GB A100,不受影响。
- **bare `sbatch` 丢 `$JID`**:`scripts/hpc/sbatch_*.sh` 必须 `source scripts/hpc/submit.sh <name>` 提交。bare 提交也能跑但后续 `gpus` / `scancel $JID` 找不到 job。
