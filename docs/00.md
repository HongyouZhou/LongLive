## 1. Research Anchor

**目标**(用户 2026-05-16 明确):

> "在 few-step 模型基础之上,改进模型的 mode seeking 问题。MotionDirector 是一个 idea。"

**无歧义版本**:

- **要解决**:DMD reverse-KL 的 mode-seeking ceiling → motion amplitude collapse(详 §2)
- **Base**:Wan-1.3B 4-step(`longlive_base.pt`,NVlabs 已 DMD distill 完的 ckpt;
  或路线 2 训出来的新 1.3B few-step)
- **MotionDirector / forward-KL / MLE 是 mode-covering 的具体实现手段**,不是 framework

**两条 candidate idea(平等地位,无 baseline / main contribution 之分)**:

### 1.1 路线 1 — sequential post-hoc MD finetune

```
vanilla Wan-14B → [DMD,已完成] → longlive_base.pt → [+LoRA+MD MLE] → few-step + motion
```

- 起点:`longlive_base.pt`
- 操作:挂 LoRA + MotionDirector MLE loss 在 base **之上** finetune
- DMD trainer:不动(完全符合"DMD 架构不动")
- 复用 NVlabs ckpt:✓

### 1.2 路线 2 — joint forward + backward KL distill

```
vanilla Wan-14B → [DMD reverse-KL + MLE forward-KL joint distill] → few-step + motion
```

- 起点:vanilla Wan-14B teacher
- 操作:DMD reverse KL(mode-seeking)+ forward KL / MLE(mode-covering)同时优化,
  一次蒸馏出 1.3B few-step student
- DMD trainer:**改**(加 forward-KL 项 → 跟"DMD 架构不动"有 tension,需 explicit
  讨论)
- 复用 NVlabs ckpt:✗(从 vanilla Wan-14B 重新 distill)

### 1.3 两条路线核心差异

| 维度 | 路线 1 | 路线 2 |
|---|---|---|
| mode-covering 信号注入时机 | post-distill | distill 时 |
| 是否动 DMD trainer | 否 | 是 |
| 复用 longlive_base.pt | 是 | 否 |
| compute cost | 小(只 finetune 1.3B) | 大(从 14B teacher 重 distill) |

**已弃 framing(别再用)**:
- "Phase 2 / Phase 3" multi-stage framework(teacher LoRA → size-asymmetric DMD)
- "Option 1 baseline / Option 2 main contribution"(paper-写作 framing,不是 idea-探索)
- "MotionDirector mode-covering finetune on few-step model" 当成单一 framework
- 在 DMD 内部找 dfake_gen_update_ratio 等旋钮(alpha sweep 已证伪)

## 2. Motivating Analysis — Amplitude Collapse

DMD-distilled 4-step student 在 motion 上有结构性 amplitude collapse。MotionDirector
eval 协议的 motion_fidelity 用 cosine,完全不惩罚幅度衰减 → +10% headline 隐藏 -67%
amplitude 代价。

### 2.1 历史实验:size-asymmetric DMD 蒸馏(2026-05-13~15)

用 MotionDirector loss 在 Wan-14B teacher 上挂 LoRA(rank 64,UCF Skateboarding,
500 步),再用这个 teacher 跑现有 DMD distillation 到 1.3B student(3000 步,
8×H200,29.2h)。Eval(LOVEU 304 + UCF 60 = 364 prompts):

| Metric | baseline | DMD-distilled student | Δ |
|---|---:|---:|---:|
| motion_fidelity | 0.390 | **0.430** | **+10.3%** |
| temp_consist | 0.9708 | 0.9804 | +0.0096 |
| pick_score | 21.39 | 21.55 | +0.17 |
| app_div | 27.18 | 27.02 | −0.16 |

协议内 net positive。但 post-hoc CoTracker3 tracklet amplitude:

| Metric | baseline | student | Δ |
|---|---:|---:|---:|
| mean_velocity_px | 4.84 | **1.59** | **−67%** |
| total_path_px | 58.5 | 22.1 | −62% |
| max_displ_px | 41.9 | 16.6 | −60% |

VBench Dynamic Degree(RAFT,community-standard amplitude proxy)独立验证 -65%。

**Reframe**:protocol 报 +10% 是因为 motion_fidelity(Yatim cosine)只测方向不测幅度;
方向更准、幅度塌成 1/3,cosine 算赢但视觉上 motion 明显减弱。

### 2.2 Alpha sweep — 定位 root cause

假设:Phase 2 LoRA 的 `lora_alpha` 是 amplitude 旋钮(inference 时 reattach 不同 α)。
实验:α ∈ {64, 32, 16, 8} × 6 Skateboarding prompts,full-step Wan-14B + 同一
teacher_lora_final.pt:

| alpha | mean_v_px |
|---|---:|
| 64 | 10.05 |
| 32 | 11.27 |
| 16 | 10.68 |
| 8 | 10.15 |

α 64→8(强度降 8×),mean_v ~10 px/frame,无单调趋势。**LoRA 强度不是有效旋钮**。

把所有 amplitude 数字摆一起:

| Setup | denoising steps | LoRA on teacher | Skateboarding amp |
|---|---:|:---:|---:|
| baseline 4-step student | 4 | — | 13.52 |
| DMD-distilled student(teacher 带 LoRA) | 4 | rank 64 α 64 | 2.51(-81%) |
| Sweep α=64 | 50 | rank 64 α 64 | 10.05 |
| Sweep α=8 | 50 | rank 64 α 8 | 10.15 |

→ collapse 发生在 **DMD distillation 内部**(teacher 10 → student 2.5),不在 teacher
LoRA 注入侧。

### 2.3 结论

amplitude collapse 是 **DMD reverse-KL × 4-step 的 mode-seeking ceiling**,结构性,
不靠 hyperparams 修。这是 anchor 的核心 motivation。

### 3.1 5-metric 出处(权威)

| Our column | 真实源头 | MotionDirector paper 用吗? |
|---|---|---|
| `app_div` | LOVEU-TGVE `clip_score_text`(CLIP-L/14)| ✓ |

## 4. Distillation Algorithm Shortlist

按 mode 行为分 5 类。详细 paper-by-paper 分析见 git history 的 docs/06(已合并)。

| 类别 | 代表 | Mode 行为 | 跟当前 Wan-14B / Self-Forcing setup 兼容 |
|---|---|---|---|
| reverse-KL distribution matching | DMD / DMD2 | mode-seeking | ✓(当前 baseline) |
| Fisher / forward-KL(在 score 域)| **SiD** | mode-covering | ✓ Self-Forcing 已支持,改一行 yaml |
| Trajectory regression(consistency)| LCM / AnimateLCM | mode-covering | △ 重写 trainer |
| Adversarial | ADD / LADD / GAN head | discriminator-defined | △ 加 D 网络 |
| Hybrid forward+reverse | **rCM** / Causal Forcing / T2V-Turbo | balanced | △ 工程量大,但研究上最 promising |

### 4.1 跟两条 candidate idea 的对应关系

- **路线 1(post-hoc MD MLE finetune)**:概念上接近"先 reverse-KL 蒸完,再 forward-KL
  finetune",时序串行
- **路线 2(joint forward+backward)**:概念上接近 **rCM 的 hybrid CM+DMD**(rCM joint;
  Causal Forcing 串行 ODE→CM→DMD)。区别:路线 2 用 MotionDirector L_temporal_MSE+L_AD
  做 forward 项,rCM 用 sCM consistency 做 forward 项。**rCM 是 sister approach,
  paper 必须 cite 并对比**

### 4.2 强候选(独立于两条 candidate idea,可作为对比 baseline)

- **SiD swap on existing setup**:Self-Forcing `denoising_loss_type: dmd → sid`,同
  trainer / 数据 / 硬件 / 步数。1.5 天可拿数据。**最便宜的 mode-covering 对比点**。
- **Causal Forcing**:README 直接 warn "≤1K DMD training steps"(我们历史实验跑了
  3000 步,batch=8,等效 batch=64 的 375 步,在推荐内但作者说 "excessive" 没给阈值)
- **rCM**:hybrid CM+DMD,直接 target Wan-2.1 1.3B,FlashAttention-2 JVP kernel
  支持 Wan-14B

### 4.3 Out of scope

- **Rectified Flow / 重训 base**:redefines setup,无 student 概念
- **Progressive Distillation**:被 Consistency 实质 superseded
- **DMD 内部魔改 / 缝 regression loss**:违反"DMD 架构不动"

### 7.4 已知坑点

- **transformers v5 API drift**:`CLIPModel.get_image_features/get_text_features`
  返回 `BaseModelOutputWithPooling`,`.pooler_output` 已 projected → 任何 CLIP-style
  embedding 走 `vision_model + visual_projection` 直接拼装
- **`lora_utils.configure_adapter_for_model`** kwarg `lora_config=` → `adapter_config=`
  (2026-05-12)
- **PEFT LoRA init 是 fp32, Wan base 是 bf16** → FSDP size-based wrap 拒绝 mixed-dtype
  → 手动 `param.data.to(bf16)` after PEFT attach,before FSDP wrap
- **`WanVAEWrapper` 是 fp32**,喂 bf16 pixel 会报 dtype mismatch → pixel fp32 给 VAE,
  encode 完 latent 再 cast bf16
- **decord cpp-extension 跟 torch 2.8 不兼容警告** — pure-Python 路径仍可用,忽略
- **40GB A100 排除**:`sbatch_motion_eval.sh` 默认 `--exclude=s-sc-dgx[01-02]`(8 worker
  × CLIP-L + CLIP-H + CoTracker3 + Wan-1.3B + T5-XXL 在 40GB OOM)
- **Charité 单卡 GRES type pin 不可靠** → 改 `--gres=gpu:8` 整节点
- **TLS 拦截代理 / 自签证书** → `prepare_motion_eval.py` 已加 3-tier fallback(system
  CA → certifi bundle → `--insecure`)
- **CoTracker3 自动下载** → 首次 run 前必须在 HPC login node(frontend)跑一次,
  pre-cache 到 `$TORCH_HOME`
